## 1. 最终决策与交付边界

沿用模块化单体、PostgreSQL、Redis、单 Celery Solo Worker 和本机存储。统一入口下按平台隔离身份、取源实现和出口策略；下载、字幕及切片取源共用这些策略。上传继续作为独立可用的输入方式。

| 平台 | 首选实现 | 出口 | 降级与发布条件 |
| --- | --- | --- | --- |
| B 站 | 专用适配器获取公开元数据、字幕及可用媒体描述，复用可靠的既有提取能力 | 国内直连优先 | 非风控的兼容性失败才考虑一次 yt-dlp 备用；412 不在同一出口重复轰炸；真实下载验收后开放 |
| YouTube | 专用适配器封装锁定版本 yt-dlp + 本地 Deno/EJS | 管理员配置的独立海外出口 | 缺出口或运行时明确报不可用并引导上传，不回退到 Mac，也不假装支持直连 |
| 抖音 | 专用适配器先解决分享文本、短链及 aweme_id，再接入经验证的取源实现 | 国内直连优先；商业接口的请求另按供应商配置 | 自维护实现先验证；签名维护不合算时才接商业服务；未验收不宣传稳定支持 |
| 上传 | 现有私有音视频上传、校验、转写和 AI 流程 | 不访问原视频平台 | 不依赖平台取源，但仍受文件、磁盘、账号额度及模型配置约束 |

没有“所有公开链接永久可用”的承诺。目标是取源故障可定位、影响可隔离、恢复不依赖个人电脑，已有成果和上传业务可以继续使用。

本次首期不做：微服务拆分、境外 Worker 集群、共享文件系统、常驻 Chromium 签名服务、住宅代理池、Cookie 上传、自动验证码、去水印承诺、SRT 导入、切片定位供应商切换。

## 3. 保留哪些契约，新增哪些内部组件

HTTP 解析继续返回现有 VideoMetadata 和 download_options；保留 /api/v1、data/error 包装、request_id、原有业务档位和认证方式。不在响应里加入服务器本地路径、供应商密钥、代理凭据或原始播放地址。

内部结构目标及当前进度如下，标注“后续”的部分尚未实现：

```text
app/modules/video/parsers/
  base.py          # 保留 VideoParser / ParsedVideo
  links.py         # A 已实现：分享文本、域名、视频 ID、短链归一化
  dispatch.py      # A 已实现：平台分发；目前注册项均用受控 yt-dlp 内核
  operations.py    # A 已实现：父进程 Redis 协调与元数据预算
  bilibili.py      # B 已实现：公开 BV/av、匿名会话、WBI、DASH/字幕；直连元数据通过，完整下载待验收
  youtube.py       # C 已实现，单样本 MP3/480p、取消与代理重启后下载通过，多日验收待完成
  youtube_runtime.py # C 已实现：Deno/EJS 离线执行与版本/散列检查
  youtube_dns.py   # C 已实现：可选平台专用加密 DNS，保留公网校验
  douyin.py        # D 已接入公开分享页与受控 SDK 备用，真实样本访问受限
  runtime.py      # A 已实现：显式按平台选择出口与运行时
  cached.py       # 保留短期缓存与 singleflight
```

复用 DownloadAdapter、SubtitleProvider、TranscriptionAudioProvider、ClipSourceProvider；必要时在 video 内增设一个 typing.Protocol 形式的来源描述获取契约。不要让 ai/transcript/clips 直接修改 Video ORM。

为了避免出现“HTTP 分发成功、Worker 仍调用旧提取器”，采用内部 PlatformSourceBackend Protocol，由隔离子进程调用。A 已统一元数据、download/child.py、transcript/subtitle_child.py 的注册表入口。B 在 platform 模式接入 B 站专用实现及受限备用。C 已接入 YouTube 专用实现，legacy 和其他平台仍使用受控 yt-dlp。D 已接入抖音实现，产生同一内部来源描述；只有明确的兼容备用路径才再次调用平台提取器。上层 VideoParser 继续包装子进程并转换成 ParsedVideo，不让 Service 直接调用 SDK。

媒体字节传输、进度和本地转码优先复用既有受控下载/ProcessRunner 内核，替换其取源步骤，不为每个平台复制一套完整下载器。新适配器必须把全局与每条流的必要请求头正确合并；对供应商返回的头按域/用途限制，不能把供应商 Authorization 或任意 Cookie 透传给 CDN。

内部来源描述包含：平台、platform_video_id、规范源 URL、实际时长、可用流/字幕、每个资源所需的受限请求头、有效期、能力及非敏感策略版本。video_id 数据库 UUID 与平台视频 ID 分开。

短期元数据缓存以规范来源身份及必要的提取/出口策略版本区分；播放地址不成为长期文件缓存键。既有转写/AI 内容缓存不因仅更换网络出口就整体失效。配置键、日志和诊断使用非敏感出口标识，不包含代理 URL、密码或密钥指纹。

API 只执行有上限的元数据请求；Worker 才准备本地媒体。业务任务仍通过 TaskService 创建，后续使用现有 file_id / upload_id / transcript_id 和受控文件接口。

同一次任务内短期复用已获取的来源描述，减少“字幕检查、音频准备”重复提取；跨进程只在受控私有通道传递。播放地址与临时凭据不写入任务/SSE/PG 的长期业务字段，也不放入命令行参数。子进程自行从服务端配置读取供应商密钥。

## 4. 链接、身份与安全边界

1. 严格 URL 输入继续兼容；新增分享文本解析时，最多接受一个 URL。多个 URL 明确拒绝，不随机挑选。前端的 new URL 校验也需随该能力小范围调整，不能只改后端后声称支持粘贴分享词。
   URL 入口先完成安全校验再查询来源缓存，缓存命中不跳过 DNS/目标检查；按既有结果 ID 读取已授权成果则不访问原平台，不因原平台断网而强制失效。
2. 精确匹配域名及其合法子域边界；拒绝 bilibili.com.evil.example、userinfo、私网及非 HTTP(S) 地址。youtu.be、YouTube Shorts/watch URL 能本地取 ID 时不发跳转请求。
3. b23.tv、v.douyin.com 的跳转按源平台选择出口，每一跳重新验证域名、DNS 和实际连接地址；最多 5 跳，跳转阶段总预算 8 秒，GET 仅流式读取必要数据。HEAD 不支持时最多回退一次 GET，仍共享原预算。
4. 共享解析总截止时间保持 35 秒，覆盖输入 DNS、短链、等待、主提取、允许的一次备用及清理；不能把各阶段超时相加。DNS 保持现有短超时。下载/字幕/切片继续受各自既有任务总时限约束。
5. 保留 NetworkGuard / 受控 HTTP transport、TLS 验证、重定向检查；FFmpeg 只读本地文件。可信代理仅豁免代理连接本身，目标 URL 不获得私网访问权；代理侧也需阻止私网目标及 DNS 重绑定。
6. B 站分 P 必须复现锁定版本 yt-dlp 的身份语义，包括已有 _pN 区分；不能将所有分 P 都压成同一 BV。先用样本和旧记录证明兼容，无法确认的分 P 明确拒绝，不能猜测后复用旧文稿。保持 (platform, platform_video_id) 唯一索引。
7. 列表、直播、付费/登录资源继续按现有范围拒绝。匿名会话标识如 buvid/ttwid 与用户登录 Cookie 区分，按平台隔离、有限期保存，不硬编码，不接收用户上传。

## 5. 出口与依赖：切断 Mac 依赖的实际要求

在三平台模式下使用一个纯配置策略函数，所有元数据、短链、字幕、音频、视频、切片取源均调用它。CDN 请求继承来源平台策略，不能见到 googlevideo.com 等域名就丢失 YouTube 路由。

阶段 A 已加入的配置最小集合（模板仍默认 legacy）：

| 配置项 | 默认/作用 |
| --- | --- |
| VIDEO_EGRESS_MODE | legacy / platform；仅用于受控迁移，不作为永久双实现 |
| YOUTUBE_PROXY | SecretStr；服务器独立可用出口，无默认 Mac 地址 |
| 平台冷却参数 | 阈值、观察窗口、冷却时间由一处配置；不按每个平台堆十几个参数 |

现有 YTDLP_JS_RUNTIME / YTDLP_DENO_PATH 继续复用，但 Deno/EJS 要求仅影响 YouTube。国内平台故障不得由 YouTube 运行时缺失引起。

platform 模式：B 站/抖音原站直连；YouTube 使用 YOUTUBE_PROXY；其他已有 yt-dlp 来源保留直连兼容入口但不新增稳定性承诺。没有显式平台规则时，不得继承全局 HTTP_PROXY、ALL_PROXY 或旧 YTDLP_PROXY。yt-dlp 使用明确直连值，HTTP 客户端禁用隐式环境代理。

专用适配器和 yt-dlp 备用都必须遵守同一出口、身份、缓存和冷却策略。B 站 412 后换同一 IP 再跑 yt-dlp 不算有效备用；音频低码率也不能解决发生于元数据阶段的风控。

独立出口可以是服务器侧进程或服务器直接连接的受控服务，需有自身运行维护与可达性验证。把变量指向仍由 Mac 转发的 localhost 端口不算独立运行。初期不采购住宅代理池；先验证实际出口。

## 6. 音频、合流和竖屏：保留现有产品能力

统一优先级：已有授权转写/成果 → 平台字幕 → 有效媒体缓存 → 合适的独立音频 → 必要且已确认预算的合流源抽音 → 上传。

转写选择足以识别的音轨，避免盲目取最高码率；用户主动导出 MP3 的现有 192kbps 产品规格不被悄悄修改。不要把处理低码率当作绕过平台风控的保证。

识别用途与用户音频导出用途明确区分：ASR 专用降码率/归一化文件首期只留在任务 tmp 目录，不登记为用户的 audio_mp3 下载结果。现有高规格 MP3 可单向复用于识别，不能将识别低规格文件反向冒充用户导出缓存。若将来持久缓存 ASR 媒体，需使用独立 preset 并同步修正当前仅按 audio/mpeg 选缓存的逻辑；优先利用已有转写缓存，避免为这一优化引入新存储体系。

抖音等来源可能只有音视频合流。拟新增“有界合流源抽音”策略必须先让报价冻结来源模式、下载体积上限和总时长，再由用户确认；确认界面说明需要下载源视频提取音轨。用户取消、源文件过大或源模式变化时停止/重新报价，不能在原纯音频预算内静默改为完整视频下载。沿用现有 ASR/AI 结算，不新增隐形扣费。

源体积未知不能按 0 预留；以账号和系统允许的最高下载上限及完整处理峰值进行存储检查。合流抽音未实现并通过报价/取消测试前，保持当前 AUDIO_STREAM_UNAVAILABLE 的明确错误及上传引导，不悄悄放宽限制。

普通视频下载继续返回真实可用档位。对竖屏、非整档分辨率和仅合流资源，不能谎称有 720p；若需新增“源画幅 MP4”业务档位，应同步改后端预设、格式聚合、前端显示和契约测试，保留旧档位兼容。

切片取源从“硬编码 video_720_mp4”改为“符合预算的可用视频源”，选择结果进入报价/任务快照。成片输出继续沿用当前最高 720p、原比例的渲染契约，不能把取源规格与成片输出规格混为一谈。

缓存源不足、缺少画面或定位服务缺失时，不创建注定失败的成片任务；在现有报价阶段明确提示。切片定位仍为独立里程碑，不能用分块 ASR 文稿伪造逐句切点。

成片的另一个前置是 FFmpeg 参数兼容：现有 -fps_mode vfr 不能直接在生产 4.4.2 上使用。优先做能力检测和小范围参数兼容，在隔离环境验证 -vsync vfr 等兼容路径对帧数、时长、音画同步及完整解码的实际结果；未经回归不能直接声明等价。若不能证明兼容，明确停用新成片任务，再单独评审 FFmpeg 升级。保留预检记录，不在 HTTP 报价进程执行媒体处理；本机新版 FFmpeg 的测试成功不能代替生产版本验收。

## 7. 缓存与平台冷却

保持 AGENTS.md 的视频身份、转写、总结和导图缓存键。媒体缓存另含实际选档、音轨、来源内容版本、B 站分 P、文件有效期；不能把过期文件或过期播放 URL 当作可复用结果。上传继续按用户及内容隔离，读取/复用保留归属、文件锁、到期和额度判断。

平台协调放到现有 Redis，不增加新基础设施。初始可调策略：同一平台 + 非敏感出口/供应商标识，在 60 秒内连续 3 次明确风控/限流后冷却 300 秒；仅当完整验证显示需要时再调整。

Redis 协调由 API/Worker 的父进程负责：操作开始前申请许可，结束后按 operation_id 原子登记一次结果。受 NetworkGuard 全局 socket 检查的取源子进程不连接私网 Redis/PG，只通过私有协议报告脱敏结果；这些事件先由父进程验证，不能直接转发 SSE。防止“父子进程各记一次失败”以及正常 Redis 连接被子进程 SSRF 检查误拦。

只统计 SOURCE_ACCESS_RESTRICTED、SOURCE_RATE_LIMITED 等可明确归因的结果；404、内容删除、登录要求、用户取消、磁盘不足、模型故障不熔断整个平台。CDN 签名过期先在原总预算内刷新一次来源，不直接算平台风控。

计数由真实上游操作结果更新：有资格的源站成功清零连续失败计数；缓存命中及不计入的错误不伪装成源站恢复。观察窗口到期可重置计数，状态更新须保留代次/持有者校验。

错误判定必须结合请求阶段和明确原因，不能沿用“任意 HTTP 403 都是平台风控”的推断：元数据 412/明确 Bot/429 可计入；供应商 401 属于供应商配置故障；CDN 403 需区分签名到期与真正拒绝。无法确定的失败返回可读错误，但不靠猜测累计全平台熔断。

缓存和已有成果优先；冷却只阻止新增上游请求。半开时只放行一个有 TTL 的轻量探测，成功恢复、失败续冷却，取消/进程退出不能永久占住探测资格。队列中即将发起请求时再检查一次状态。

每个成功/失败报告与许可绑定并幂等，迟到报告不能覆盖新一轮半开状态；探测许可 TTL 覆盖该操作的总截止时间和清理宽限，释放须核对持有者。冷却不强行中断已获许可且正常进行的媒体传输；该传输仍按自身取消/超时/大小控制，收到自身风控错误则结束。

保留已有单进程请求合并，补足跨 API/Worker 的共享限速：每平台同时最多一个“元数据提取”操作，等待有界；长媒体传输不长期占用元数据锁。单 Worker 仍控制媒体任务串行。

Redis 失败时不静默取消限速或改为无限直连；新增取源快速返回 DEPENDENCY_UNAVAILABLE。已授权、无需 Redis 协调的历史成果读取按既有服务能力处理，不承诺所有 Redis 依赖接口都可继续。

## 8. 预算、重试与服务器保护

- 维持一个 Solo Worker、-c 1；账号会员并发额度不代表服务器并行能力。初期不增加签名浏览器、第二个下载 Worker 或跨机同步。
- 维持 STORAGE_MAX_QUOTA_MB=5120、生产最小空闲空间保护和现有媒体 TTL；下载前预算包含源文件、合并/转码、WAV、切片中间件及输出峰值。不能只按最后一个 MP3 的大小预留空间。
- 分开计量平台到服务器的来源入站、网站到用户的文件出站、出口/供应商计费。不能把账号每日文件下行额度直接当成平台入站额度，或对同一项重复扣费。
- HTTP 请求明确连接/读写/总截止时间；版本/可达性探测短超时。不新增 SDK 自带无限重试，也不叠加适配器、Celery、HTTP 客户端各自三次重试。
- 一次提取最多主实现一次、符合条件的备用一次，受共享总预算限制。412/Bot 等不在同一出口立即重试；短链 GET 回退同样计入预算。
- “一次提取”是有界逻辑操作，不代表只允许一个 HTTP 请求。每个实现须声明必要的上游请求数上限，并在测试中验证；SDK 内部重试与签名刷新也计入同一总预算。
- 媒体传输失败后如允许重新取源，先关闭原连接并清理 partial，再重新检查预算；禁止拼接两个不同来源的残片。
- 子进程保持 start_new_session=True、500ms Watchdog、取消标记/总超时/文件体积检查、SIGTERM→SIGKILL、退出确认、清理和终态 CAS。供应商 HTTP 取消需关闭本地请求；上游不支持取消时，也必须受调用次数和费用上限控制。
- API、供应商返回、日志及诊断不回显 Cookie、Authorization、代理凭据、带签名的 CDN URL 或本地私有路径。

这些是本轮改造的 A–E 里程碑，不是对历史阶段的重新编号。每次只实施被明确启动的里程碑，不从本文推断跨阶段编码授权。

| 里程碑 | 修改范围 | 验收与停止条件 |
| --- | --- | --- |
| A：基础与出口分流 | 链接规范化、平台分发、显式网络策略；保留现有实现作为兼容内核；共享冷却、服务账户能力预检 | API/Worker/字幕/切片全部调用点审计通过，三平台出口无串用；没有独立 YouTube 出口时标记该平台未验收，不购买或伪造出口 |
| B：B 站专用实现 | 元数据、字幕、音轨、视频、分 P 身份兼容、受控备用 | 独立国内直连真实样本验证；持续 412 时保留上传，不通过 Cookie 注入或频繁轮换 IP 掩盖问题 |

| E：持续实测与发布 | 样本清单、统计、版本化发布、配置迁移、独立出口验证 | 达到下一节门槛才逐个平台启用；失败不拖累其他平台和上传；不把真实 AI/定位验收混进免费取源测试 |

## 10. 测试、统计和可发布标准

### 10.1 离线与隔离集成

覆盖：域名边界、分享词/多 URL、全部重定向跳、DNS 重绑定、代理远端 DNS、环境代理泄漏、YouTube 缺出口/缺运行时、B 站分 P、CDN 签名失效、合流无独立音轨、竖屏无精确 720p、缓存到期/归属、Redis 故障/并发冷却/半开、总时限和备用预算、取消后子进程树退出、终态 CAS、报价幂等与失败释放。

成片能力测试额外覆盖当前生产 FFmpeg 4.4.2 的实际参数能力与输出质量；无法覆盖就保持未验收。供应商只返回合流、上游分辨率改变、来源模式在确认后变化时，也必须验证安全拒绝/重新报价，而不是降级后超预算继续。

必须有跨 API/Worker 的链路测试，防止只验证 ParserRouter 而下载子进程仍绕回旧逻辑。新增前端分享文本、报价说明或档位能力时，运行对应类型检查、单元测试及生产构建。

### 10.2 真实服务器样本

每平台至少 30 个预登记的独立公开视频样本，分布在至少 3 天，覆盖多个发布者、长短视频、短链、音频/视频源形态及不同清晰度；另列删除、私密、直播、登录/地区限制等预期失败样本。

样本先核对现有账号时长/体积限制。普通公开样本发生 412/Bot 仍计失败，不得事后移出分母。不同视频、同视频重复请求、缓存命中、冷却拒绝、主实现成功、备用成功分别统计。

真实媒体验证必须完整落地，FFprobe 核对时长和音/视频轨，再对有界文件执行完整解码检查。API 标题成功、读取 1KiB、仅 HEAD/206 响应不算完整下载成功。测试需要走 TaskService/Celery、现有认证和资源限制；不得临时关闭计费/SSRF或签发冒充用户的令牌。

对完整性另设时长误差阈值和来源身份核对，避免容器能打开却只含试看/截断内容；供应商回显请求 ID 不等于媒体内容正确，应对已知样本抽查音视频内容。公开免登录范围内不把会员试看当作完整资源交付。

按元数据、独立音频、有界合流抽音、视频、字幕分别给出分子/分母、耗时、字节数、错误类型、出口/实现版本。字幕仅对预先确认有公开字幕的子集评估；没有字幕应能按确认预算回退音频。

首期工程门槛建议：元数据至少 29/30；所宣传的音频/视频取源能力各至少 27/30；安全、归属、幂等、取消及其他平台隔离测试全部通过。小样本指标仅作为发布门槛，不是长期 SLA。某能力无足够样本则标记未验收，不用其他能力代替。

门槛按预登记的合格逻辑请求样本计算，冷却拒绝也是该样本未交付，不能删掉分母；另报“实际发起的新鲜网络操作”的成功率，后者不纳入根本没有发出的缓存/冷却请求。两组指标并列，防止供应商请求成功率很高、实际用户却频繁被拒绝的误判。

生产缓存不得为了测试被全局清空；基准任务使用隔离记录和测试账号，缓存命中单列。测试流量按天限额，遇连续风控立即遵守冷却，不为凑样本高频请求。真实 ASR/LLM/定位和付费解析调用另列费用预算，不自动批量触发。

执行前先按现有免费每日 2 次下载、免费/会员 1/5GiB 每日下行、256/512MiB 单文件、20/60 分钟时长、实际平台出口费用及 5GiB 总存储核算计划。30 个样本/平台、至少 3 天是样本要求，不能理解成免费账号 3 天内完成至少 90 次完整下载。确需更高测试额度，使用管理员现有受审计的测试账号权益发放流程并取得相应授权；否则延长周期。转码/WAV/输出峰值和媒体 24 小时保留也计入磁盘预算，不能为测试擅自删除其他用户有效文件。

### 10.3 商业服务采用条件

只有某平台未达到门槛且有明确维护成本时才进入试用。记录实际单价/计费单位、失败是否计费、缓存与重试是否重复收费、支持的平台/格式/地区、限速、数据流向、维护响应及服务承诺。不能把未经核实的“几厘一次”写进成本模型。

商业适配保持现有来源契约，原始媒体 URL/响应同样做 SSRF 与有效期校验。首次试用设调用/金额上限；公开解析入口不能无预算地自动消耗供应商余额。供应商切换影响费用或来源模式时重新获取确认，不复用失真的旧报价。

供应商取源成本属于需要单独记录的运营成本，不能擅自从用户转写分钟或 AI 次数中扣除。主/备供应商的付费调用默认关闭，启用前明确调用上限、费用承担和失败收费规则；不能在还未取得用户任务报价时进行无预算的付费回退。

## 11. 上线、回滚与运维

1. 本地分支开发 → 全量测试 → PR/CI → main CI 的确切发布产物 → 现有 Deploy production。配置和密钥不进入仓库。遵循 [现有部署说明](deploy/CD.md)。
2. 为每个平台记录能力状态与出口就绪状态。/health/ready 继续只检查 PG/Redis，不因 YouTube 不通令全站 readiness 失败；平台诊断通过受控 CLI/管理员能力提供。
3. API 与 Worker 读取同一份版本化策略。双环境模板和生产模板一起维护；源代码更新不能覆盖生产 backend.env。配置状态只输出脱敏标识及版本，不输出密钥哈希或原值。
4. 切换旧 YTDLP_PROXY 前核对活动/排队任务及旧输入身份。小规模首版选择维护窗口，先停止新增任务，正常收尾；未清空需兼容的旧队列就延期，不强杀或静默丢弃。已有终态文件/成果继续可读。
5. 先证明目标平台可在服务器独立工作，再退出 Mac 临时出口。YouTube 独立出口未准备好时可明确停用新 YouTube 取源；B 站若直连仍失败则提示上传，不能假装改造已经消除了风控。
6. 为代码和配置分别保留回退点。没有数据库变更时沿用既有兼容回滚；如实施中确需身份/资源字段迁移，单独评审迁移及恢复，不默认代码回退能回滚数据库。
7. 旧全局模式只留一个受控兼容窗口；新三平台链路无调用者后删除，避免长期维护双路代码。兼容窗口内禁止部分 Worker 用旧策略、部分 API 用新策略。
8. 按天查看各平台成功率、冷却/恢复次数、取源字节数、任务排队时间、磁盘峰值和供应商费用。依赖锁定版本，维护升级先跑样本回归再上线；不在 Worker 启动时自动更新 yt-dlp 或下载远程执行组件。

## 13. 审查记录与实施前检查

本节在逐轮审查后补充实际发现与修正，不把文档审查当成测试通过或线上能力已实现。

### 第一轮：架构与契约

已核对现有 Protocol、输入解析、Worker 及上传闭环，确定保留 HTTP 输出与任务编排；去掉在解析响应中返回本地文件路径的设计，要求全链路出口一致。

### 第二轮：全链路、资源与故障

发现并修正：仅增加解析分发不能覆盖两处 Worker 重新提取；明确内部来源 Backend 与三个子进程的共同入口。补齐合流抽音确认预算、竖屏与非 720p 取源、请求头作用域、父进程 Redis 协调、半开并发/迟到报告和 403 分类，避免状态污染及循环重试。

### 第三轮：成本、验收与发布

发现并修正：免费每日下载次数不足以在三天内跑完三平台样本，测试必须先核算账号/流量/磁盘预算；区分缓存与新鲜取源成功率；要求完整文件、时长、内容与解码验收；商业取源费用不混入 ASR/AI 账务。保留分平台发布门槛、策略同步切换、既有成果可读和配置/代码分别回退。

### 第四轮：实际服务器与一致性复核

通过 SSH 只读探测确认服务器为 FFmpeg 4.4.2，帮助输出不存在 -fps_mode，存在 -vsync；因此补上独立于定位模型的参数兼容验收。部署账户 PATH 无 Deno 只记为线索，不当作服务账户结论。再次修正未知源体积不能按零预算、入站/出站/供应商三类成本必须分开、缓存命中不能重置平台故障、ASR 低规格音频不得冒充下载缓存及两个成功率分母等边界。文档本地链接和代码块已校验。

### 方案审查的结束条件

当前四轮审查已明确内部调用边界、输入/输出兼容、身份、出口、超时/重试、缓存/权限、熔断、资源预算、账务、测试、分平台发布及回退条件。继续迭代应由新的代码证据、实测结果或需求变化触发，不能把重复文字审查当作成功率验证。

实施前仍需逐项取得证据：独立 YouTube 出口和费用；B 站直连与抖音真实取源结果；测试账号/流量预算；FFmpeg 兼容回归。完整成片发布另需真实时间戳定位服务。未取得证据时停在对应能力边界，不宣称三平台完整业务全部可用。
