**4. P1 修复：进程、任务与合法切片**

F01 的位置与触发链：

- [Qwen 临时目录](/Users/edgar/Desktop/项目/videohub_ai/backend/app/modules/transcript/providers.py:202) 在任务目录内另建 asr-chunks 子目录。
- [ProcessRunner 标记](/Users/edgar/Desktop/项目/videohub_ai/backend/app/infrastructure/process_runner.py:133) 写在调用方传入目录，而不是统一任务根目录。

修复采用统一“任务级进程登记”契约：每个外部进程有 operation_id，记录 task_id、已有 attempts 代数、主机、进程组和工作目录；调用方即使使用子目录，登记也归属于任务根目录。标记使用临时文件原子替换，不能直接截断写正在使用的 JSON。保留旧根目录标记的兼容读取，并有界扫描旧任务中已有的嵌套标记；新增任务不只保存“最后一个 PID”。

恢复、任务目录清理、上传删除和源媒体回收统一查询这一契约。确认所有已登记组退出后才能删除文件和释放预留；无法确认则保留对应任务资源并给出可核查原因。不得用 TTL、根目录无标记、父 Worker 不存在或“最后一个进程已退出”代替全体进程检查。故障测试必须使用真实独立进程组，并在 finally 停止测试自己创建的进程。

F02 位于 [execute_plan 启动](/Users/edgar/Desktop/项目/videohub_ai/backend/app/modules/clips/worker.py:60) 与 [execute_export 启动](/Users/edgar/Desktop/项目/videohub_ai/backend/app/modules/clips/worker.py:166)。将启动、启动后读记录、预算装配和日志初始化纳入同一个受保护的执行入口。

入口应保存本次是否取得执行权及 attempts 代数，不可让重复投递的任务失败处理覆盖真正执行者。启动或完成回复不明时先有界核对 PostgreSQL；不能重做已经开始的 ASR/LLM，也不能只因网络错误退款。明确由本次取得执行权、尚未启动外部工作时，可通过条件更新安全失败/取消并释放额度。

若短暂数据库故障使最终状态也无法写入，记录本次尝试已停止的恢复凭据，独立 reconcile 据 attempts 与任务级进程登记完成收敛。不能仅因 Worker PID 仍在就永久跳过已经停止的尝试，也不能用心跳过期直接回收仍运行任务。优先复用现有 attempts，不为此重写整套任务平台；旧任务缺少新凭据时继续走保守兼容分支。

F03 位于 [定位临时音频清理](/Users/edgar/Desktop/项目/videohub_ai/backend/app/modules/clips/worker.py:144)。清理必须依赖进程退出凭据；PROCESS_CLEANUP_FAILED 或控制状态不明时保留音频、控制标记与必要容量保护，交由上述恢复契约处理。HTTP 已结束且没有进程读写时仍应及时清理，不把所有失败文件都永久保留。

同类 finally 与 TemporaryDirectory 退出都必须复用这一判定，包括 Qwen 的临时分段目录；只修 clips 的一个 unlink 仍会留下同类故障。A15 验证了后一处，因此列为同一根因的第二个调用点，不重复计为新的独立缺陷。

F04 位于 [定位后加留白](/Users/edgar/Desktop/项目/videohub_ai/backend/app/modules/clips/worker.py:148)。区分不可截断的语音核心区间与可选播放留白：先验证核心区间，再在源边界、邻接片段和时长剩余量内分配留白。核心已满 90 秒时留白为 0；两个核心恰好相邻时不把留白扩进对方。真正核心重叠或核心超长仍应拒绝，不能通过截断内容或放宽上限掩盖问题。

本批验收必须使 A01/A02/A04/A09/A10/A15 转为正确行为：相邻合法片段成功、上限片段成功、启动异常不留下占用、所有未退出组的资源保持、进程确认退出后才释放。额外测部分登记、损坏登记、数据库回复丢失和重复恢复，确保终态及账务各一次。

F05 位于 [locate 候选判断](/Users/edgar/Desktop/项目/videohub_ai/backend/app/modules/clips/timing.py:44)。先寻找唯一精确匹配，再做受限近似匹配；同一个语句的重叠/包含区间归为一处，不能与两个时间上分离的重复台词混为一谈。保留比较次数和时间预算，但提前确定的唯一精确匹配不应被大量近似包含区间推翻。

**6. P3 优化：按片段复用，批次只负责交付**

O01 的根因是 [定位缓存键](/Users/edgar/Desktop/项目/videohub_ai/backend/app/modules/clips/worker.py:117) 和 [成片缓存键](/Users/edgar/Desktop/项目/videohub_ai/backend/app/modules/clips/service.py:114) 都带整组选中 ID。

将缓存分为窗口/候选定位与单片媒体资产两层；批次聚合这些资产。单片键包含用户范围、源 SHA-256、最终区间、精细时间轴版本、输出 profile 和 renderer 版本；从原批次选择子集时优先复用仍有效文件与原 expires_at。读取新组合不会让文件无限续期，也不分享其他用户私有内容。

现有 ClipExportItem.file_id 是唯一字段，同一 file_id 不能出现在多个批次。实施本优化需要增量迁移：允许文件关联多个批次，至少以 `(export_id, file_id)` 保证批次内唯一；或者引入独立媒体资产关联。授权仍通过已成功且属于当前用户的批次及媒体契约判断。迁移前确认历史唯一关系可无损保留，不删除结果与授权。

批次仍维持整批交付；复用资产和新渲染资产均在提交前校验可用性，并在同一数据库事务登记。混合有效期按每条返回，不偷偷延长旧文件 TTL。该优化放在正确性修复之后，不作为第一批上线前修复的前置依赖。
