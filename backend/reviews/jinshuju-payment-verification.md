状态：已完成凭据认证及账号表单 API 只读实测；当前 API 无可查询表单，尚不能验证六个收款页的真实到账状态。

## 账号级验证所需准备

用户在 https://next.jinshuju.net/profile/api 按官方步骤创建 Access Token，将其写入本地 backend/.env 的 JINSHUJU_ACCESS_TOKEN。不要发到聊天、写到代码或提交仓库。官方文档未声明个人 Token 具备单独只读权限，验证程序本身严格只使用 GET。

## 下一步只读验证

1. 认证并查询账号所属表单，验证免费版实际 API 权限，不泄露无关表单内容。
2. 获取六个收款页与表单/收款项目的真实映射，不把 /p/ 后缀直接猜作 FORM_TOKEN。
3. 检查已有付款记录（若存在），确认服务端可读取以下信息：收款主体、付款状态、金额/币种、唯一支付标识、订单/用户关联标识。
4. 对比已付与未付记录，确认该状态是金数据收款系统生成且不可被填表人通过普通字段伪造；普通 total_price/手机号/备注不算支付证明。
5. 检查可否按稳定标识查询增量或按单号查询，以及迟到付款/退款是否可见。
6. 检查现有免费版收款页是否支持可靠订单归属，不使用“相同金额 + 相近时间”自动认领。

## 判定规则

- 支付事实、交易唯一性、订单归属三项都可验证：进入免费 API 定时查款 + 幂等发放方案。
- 若缺少历史样本，可先完成接口结构核验；需要新实付样本时由用户亲自支付，经明确安排后进行，不代付款。
- 只能查询普通表单字段，或无法验证交易状态/归属：现有接口不满足自动核款条件；不以人工核款作为正常流程替代，不编写自动发放逻辑绕过验证。
- 没有账号凭据：保持“未完成账号实测”，不能得出免费版一定可行或一定不可行。

## 账号实测追加

使用用户已配置的 Token，只调用文档公开的 GET 接口，禁止认证请求跟随重定向；单请求超时 12–15 秒，无无限重试。

| 请求 | 实测结果 |
| --- | --- |
| GET /api/v1/me | HTTP 200，账号显示名 Edgar；未输出邮箱、手机号、账号 ID 等信息 |
| GET /api/v1/forms?include_transactions=true&limit=100 | HTTP 200，total=0、返回表单数 0、无下一页 |
| GET /api/v1/forms | HTTP 200，total=0、count=0、无下一页 |

普通列表与包含收款统计的列表都为空，不是分页漏查，也不是 Token 认证失败。当前 Token 未提供可继续读取的数据源，无法验证支付状态、唯一交易号或订单归属。不能把 /p/ 后缀猜成表单 Token 请求未文档化接口。

官方文档的 include_transactions=true 仅说明表单收款汇总（已支付与退款中订单的汇总金额/数量），这类聚合数据不能作为某笔订单成功付款的证明。官方文档 sitemap 共列出 62 个页面，未发现单独命名的 payment/transaction/order/checkout API 文档；此结果表示尚未找到公开接口，不证明平台绝不存在其他能力。

待用户确认 Edgar 是否就是创建这六个收款链接的账号。若不是，需改用正确账号 Token 后重测；若是，则当前免费表单 API 路线无法验证现有六个收款页，应向金数据取得独立收款页的官方查款/订单关联接口说明后再评估。没有完成任何真实支付样本验证，不能宣称自动核款已通过。

## 收款账号确认与最终公开资料核验

用户确认：Edgar 就是创建六个收款链接的同一账号，排除目前已知的账号不一致原因。

官方快捷收款说明：https://help.jinshuju.net/v4/articles/quick-payment/

- 快捷收款「不用建表单」，与表单收款是不同产品；官方体验收款链接同样使用 /p/ 路径，与用户现有链接形态一致，可解释为何收款项目存在而普通表单列表为空。
- 文档提供收款页后台查看订单、交易号搜索、Excel 导出和退款操作，未提供快捷收款的公开查单端点。
- 自动发货说明为付款后展示预置文件或链接，未说明每单唯一卡密库存或可验证的动态订单参数；不能据此宣称可安全自动发放本站会员。
- 官方说明免费版每月收款额度上限为 500 元，付费版不限；实际账号和商户协议仍以后台为准。

交易中心官方说明：https://help.jinshuju.net/next/articles/Transaction/

- 支持商户后台查看、筛选、搜索及导出真实交易。
- 明确说明暂不支持定时自动导出；未列出公开订单查询 API。

验证结论：当前「免费表单 API → 六个快捷收款页付款记录 → 自动核款」路线未通过，不能作为自动开通依据。已确认认证有效与同账号，普通表单 API 没有数据源；没有取得快捷收款支付状态、唯一交易号及本站订单归属的服务端验证能力。不代表平台绝无非公开或其他套餐能力，需金数据官方明确提供适用于 /p/ 快捷收款的接口及权限说明后才能改判。无需用户再反复更换当前同账号 Token。尚未付款、改配置、开通会员或接入未文档化后台接口。

下一步必要条件：取得快捷收款的正式查单/回调与商户订单关联文档；单独升级“表单 Webhook”套餐并不能证明能处理快捷收款。若平台明确不提供，则当前渠道无法满足用户要求的无人核款流程，应选支持正式支付查单/验签通知的渠道。
