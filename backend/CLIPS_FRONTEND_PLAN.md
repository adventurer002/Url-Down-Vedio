## 1. 最终建议与首版边界

在当前内容工作台新增第五个分区“精彩切片”，复用内容来源、账号、额度确认、后台任务、任务历史和文件下载机制。流程为：

**设置查找条件 → 确认分析额度 → 审阅候选 → 勾选片段 → 确认生成 → 后台整批处理 → 逐条下载。**

产品操作分成“找精彩片段”和“生成视频”两步。一次分析得到的候选可以多次选择，不为更换选择重新分析；只有用户改变主题/时长等查找条件并明确确认时，才创建新的分析任务。

首版包含公开视频链接、本地视频、可解析且符合资源限制的已结束直播回放；音频可寻找精彩段落、阅读/复制原文。首版不包含实时直播录制、实时出片、拖拽时间轴、手工改起止、竖屏重构、字幕烧录、封面生成、拼接、发布到平台或 ZIP 打包。后端只有固定 MP4 输出档位，界面不提供无法执行的格式/画幅选项。

首版以“可审阅、可生成、可下载”为完整闭环。稳定的服务器在线播放放到后续单独扩展，避免把下载接口误当成已经完备的播放器接口。

## 5. 四个主要界面

### 5.1 设置与分析

标题“寻找精彩片段”，说明“先找到能独立表达的内容，再选择需要生成的视频”。

- 希望找到几段：1–5，默认 3。明确“实际数量以内容完整性为准，可能少于设置值”。
- 每段目标时长：1–90 秒，默认 30–90，最小值不得大于最大值。已知原片时长 D 满足 1≤D<30 秒时，建议最大值为 max(1,floor(D))，建议最小值为 max(1,min(10,floor(D/3)))；未知时长保持默认并由后端核验，不假造时长。
- 关注方向：可选，最多 200 字，不预置夸张的“爆款”承诺。
- 首版输出语言沿用当前中文设置；不提供当前成果无法兑现的多语言配音。
- 主按钮“查看分析额度”，取得报价后显示确认框，而不是直接创建任务。

输入优先使用当前 `transcript_id`，否则使用有效 `upload_id` 或公开 `url`，三选一。已有文稿时不强制用户先重新提取，也不因为原片已删就阻止文本分析。没有文稿时，后台任务内部获取字幕/转写，前端不另建一个转写任务再串行等待。

分析确认显示后端 `maximum.asr_seconds`、`maximum.ai_generations`、有效期；成功后按实际结算。无合适候选是正常结果，显示原因与调整条件/查看原文入口，不显示失败图标，也不自动重试模型。

### 5.2 候选审阅

每项：复选框、标题、“约起止时间 / 待定位”、原文摘要、入选理由、“查看原文”。完整 quote 在详情显示，可复制，不通过 `innerHTML` 渲染模型输出。

- 默认不勾选，由用户确认；线框的 `?selected=2` 只用于展示勾选效果。
- 保持后端给出的候选优先级；不把 `score`、match 或完整性分数包装成“爆款概率/准确率”。
- 所有候选仍需生成阶段精细定位。coarse ASR 的多个句子可能共享很长或相同的时间段；前端不得依据这种时间范围计算硬性重叠、截断候选或阻止选择。
- 只对数量和 ID 归属进行确定的客户端校验；最终重叠、时长和源范围由后端处理。粗略总时长不能显示为确定的成品时长，不准确时直接写“最终时长待定位”。
- 点击时间/查看原文跳到**该方案绑定的 transcript_id**，不能跳到用户后来生成的另一版文稿。
- 改查找条件只是编辑草稿；只有确认新分析才产生新任务。旧候选与旧成品继续可读，新结果明确接受后再切换方案并清空旧勾选。

### 5.3 生成与确认

底部“已选择 N 段 / 查看生成说明”。0 项禁用，1–5 项可请求专属导出报价。

确认框展示：所选片段、输出 MP4 / 最高720p / 保留原比例、本次转写与 AI 最大占用、处理频率政策、报价有效期。禁止显示 1080p、竖屏裁剪或可编辑边界。

关键文案：“本次不消耗转写和 AI 次数，仍受每日处理次数及下载流量限制。实际开始处理后，失败或取消也可能占用处理次数。”

两个额度为 0 **不能推断导出命中了缓存**：目前所有导出报价都是 0 ASR / 0 AI。只有服务端任务结果明确 `cache_hit` 时才显示“复用已有视频”。当前也没有每日剩余次数查询，不能用 max_daily_exports 渲染“今天还剩 N 次”。最多显示后端报价给出的每日上限政策。

确认后冻结 plan_id、revision、候选集合、profile、quote_id；提交中禁用改选和重复确认。一份内容首版只保留一个进行中的分析、一个进行中的导出；仍可阅读旧结果。后端按账号串行准入，前端不能承诺并行加速。

任务阶段显示“准备源视频 → 核对起止位置 → 生成视频片段 → 检查并保存”。缓存可能跳过阶段，不能要求每个阶段依次出现；后端没有当前文件序号和可靠 ETA，不从 progress 猜“正在生成第2/3条”或“剩余15秒”。

整批成功后一次显示新结果。没有后端部分成功接口，不能在总任务结束前展示一个“已完成”的新片段；此前已交付的旧成品保持可用。

### 5.4 成品

每项显示标题、精确源区间、实际时长、文件大小、各自 expires_at、下载状态，以及单独的“下载视频”。输出属性未返回或无法确认时不要从文件名猜分辨率。

- 复用项保留原到期时间；新项与旧项可能不同。不要只放一个批次倒计时，也不因刷新或重新请求而给所有卡片续期。
- `download_available=false` 不一定代表“已过期”。已过 expires_at 显示“已到期”；尚未到期但文件不存在则显示“文件不可用”，允许刷新状态或重新报价。
- 不把 `task.status=completed` 或历史 `download_available` 当作所有成片的可下载真相，必须加载 `GET /clips/exports/{id}` 的逐项状态。
- 单个按钮获取单个 file_id 的新短期凭证，然后沿用浏览器原生下载。首版不做“全部下载”，避免浏览器多文件拦截和流量/权限确认不清。
- 下载点击只提示“已请求下载，请查看浏览器下载列表”，不在 anchor.click() 后声称“文件已保存”。不为了下载把大视频完整 fetch 成 Blob。

## 6. 来源与可用性矩阵

| 情况 | 分析 | 生成/取回 | 页面策略 |
| --- | --- | --- | --- |
| 有当前文稿、原片有效 | 优先复用文稿 | 可报价 | 正常流程 |
| 无文稿、视频源有效 | 后台取得字幕/转写 | 得到候选后再报价 | 不要求先手动做转写 |
| 原片删除/到期、文稿仍在 | 允许文本分析 | 已有资产可能可复用；新渲染需要原片 | 不全局禁用生成报价；以后端判断所选集合 |
| 纯音频 | 允许精彩段落分析 | 不支持视频导出 | 保留原文/复制入口，隐藏视频勾选与生成栏，解释需要真实视频 |
| 公共链接，source_available=null | 可以尝试正常报价 | Worker 获取源，可能失败 | 显示“生成时检查来源”，不把 null 当不可用或已确认可用 |
| 本地 file 对象还在 | 可选原片本地预览 | 与后端任务独立 | 预览不代表服务端来源仍可用 |
| 刷新后本地对象丢失 | 文稿/候选/成品照常读取 | 按服务器可用性 | 不强制重传来恢复阅读 |

`plan.source_required=true` 是原片情况，不是“任何缓存都不能交付”。用户选择子集后先取得导出报价，命中缓存则继续；返回 CLIP_SOURCE_REQUIRED 时才提示重新上传同一视频。相同内容新上传不会自动改变旧报价被冻结的实例；旧实例失效需新报价。

纯音频换成视频会改变来源身份，不承诺把任意新视频绑定到旧音频方案。重新上传“同一视频”的恢复只以服务器确认的内容身份为准。

## 7. 接口与数据契约

所有路径带 `/api/v1`；沿用现有 client 的 data 解包、错误结构及登录身份。

| 动作 | 接口 | 关键字段 |
| --- | --- | --- |
| 分析报价 | POST `/clips/plans/quotes` | `{transcript_id}` 或 `{upload_id}` 或 `{url}`；加 strategy、language |
| 确认分析/导出 | POST `/billing/tasks` | `{quote_id}`；返回 task_id |
| 获取候选 | GET `/clips/plans/{id}` | id、video_id、transcript_id、revision、spec、candidates、outcome、reason、source、source_available/source_status/source_required |
| 导出报价 | POST `/clips/exports/quotes` | `{plan_id,revision,candidate_ids,profile:"video_720_mp4"}` |
| 获取成品 | GET `/clips/exports/{id}` | plan_id、items、source_sha256、timing_usage；逐项 file_id、start/end、core_start/end、expires_at、download_available |
| 任务跟踪/恢复 | GET `/tasks/{id}`、`/tasks/{id}/events`、POST `/tasks/{id}/cancel` | 复用 seq 去重、取消确认和终态快照 |
| 原生下载 | POST `/files/{id}/download/access` 后 GET `/files/{id}/download?access_token=…` | 复用 resourceAccessUrl；不得持久化凭证 |

前端需要补显式类型 `ClipStrategy / ClipCandidate / ClipPlan / ClipExport / ClipExportItem`，并扩展 `JobKind` 为 `ai_clip_plan / clips_export`；TaskResultPayload 明确增加 clip_plan_id、clip_export_id、file_ids、outcome。`AllowanceQuote.maximum` 补可选 clip_limits，只读取产品需要的每日策略，不把内部超时或模型配置放进用户表单。

API 层新增 planQuote/clipPlan/exportQuote/clipExport 方法。它们必须走 `/clips/*/quotes`，不能因为扩展了 JobKind 就直接套用现有 `/billing/quotes` 通用方法；`api.create` 的旧路径映射也不能为切片提供未确认报价的回退。切片只从 quote_id 确认并注册任务。

## 8. 状态、版本与重复提交

组件将状态拆成三个相互独立的部分：

1. 配置草稿与确认中的报价：任务创建前可修改，改变输入立即作废当前报价。
2. 已确认任务和方案：由 task_id、plan_id、revision 与 transcript_id 固定；后台任务属于全局 workspace。
3. 本次所选候选与当前成品批次：selected IDs 只属于一个 plan/revision，不能跨方案复用。

每个报价保存完整输入指纹；导出请求将 IDs 规范为集合做防重复，但显示顺序保留服务器给出的候选优先级。**成品按 candidate_id 映射，不靠数组位置**，因为后端会排序所选 ID。片段最终播放顺序不是可编辑功能。

后端暂不支持方案 PATCH，revision 当前固定为 1；不提供“保存编辑后的方案”。改变条件是新分析，可能复用缓存，也可能再次消耗 AI，以新报价为准。

确认超时/断网属于“是否创建任务尚不明确”，保留原 quote_id 并用同一报价恢复确认，利用服务端幂等取得原 task_id；不能立刻取新报价另建任务。拿到 task_id 后，失败是任务结果，不重用同一失败任务的旧报价作为“重试”；重试应显式重新报价并确认。

成功 SSE 后依然取得最终任务快照，再获取 clip_plan_id/clip_export_id 对应资源；不依赖进度事件携带结果。网络恢复、页签重新可见时重新核验成品元数据。取消按钮进入“正在取消”，只有服务端取消终态才显示取消；若完成 CAS 已先成功则显示已完成结果。

## 9. 刷新、历史、深链与原文一致性

建议使用既有路由：

```text
/video/:contentKey?tab=clips&clip_plan=<plan_id>
/video/:contentKey?tab=clips&clip_export=<export_id>
```

导出深链先取 export，再取其 plan，验证同一 video_id 与登录账号；以服务端资源链为准，修正/拒绝 URL 中不匹配的 plan 或内容标识，禁止混合显示。

现有 `VideoWorkspaceView` 在 localStorage 没有 video 时会直接进入“找不到内容”。实现必须先增加恢复门：已登录且 URL 有切片资源 ID 时先加载资源，用 plan.source 的标题、来源和 video_id 恢复最小内容壳，再进入正常页面；不因浏览器没缓存就把有效成果判失效。最小内容壳不虚构 upload_id、本地预览或文件 ready 状态；这些操作另行恢复/核验。

任务历史的 input_payload 被服务端裁剪，不能期待它始终含 plan_id、候选集合或 upload_id。优先用 result_payload.clip_plan_id / clip_export_id；必要时读取完整 task 快照，已完成导出再 GET export 获得 plan_id。缓存命中的旧批次任务可能没有 file_ids，仍应通过 clip_export_id 打开结果。

切片的 transcript_id 来源于已打开方案，不自动跟随通用 useWorkspaceResults 切换到“最新文稿”。若需要查看原文，携带方案绑定的 transcript 参数，并保留返回切片的路径。

服务端没有方案/成品列表接口。首版可从已加载任务历史和本机保存的资源引用恢复，支持历史分页与资源深链；不能声称已经有跨设备、历史清空后也完整的“全部切片库”。清空任务历史不会删除服务器成果，但没有 ID/深链时也不能凭空列出被隐藏的成果。

## 10. 来源删除、账号与本地数据

切片任务必须进入现有全局任务注册和来源删除检查。当前上传删除管理器按内容关联非终态任务，不按旧 JobKind 白名单；接入时确认内容 key / alias 统一，避免漏掉新任务或重复展示任务卡。删除前等待服务端取消终态；超时保留原文件，不能仅在 UI 隐藏。

登录身份沿用现有 user/token 与 identityVersion。报价、资源读取、下载凭证、原片详情均绑定请求时的身份和 generation；切账号、退出、内容切换、方案切换时 abort 并丢弃迟到响应。只有 generation 匹配的 finally 才能复位当前 loading，避免旧请求关掉新请求的忙碌状态。

本地只保存用户范围内的策略草稿、资源 ID、revision、selected candidate IDs 与少量恢复元数据。原文/模型结果尽量保留内存，由服务端重新读取；不额外复制大视频、Blob、完整 quote、JWT、短期下载 URL 到本地存储。选项缓存应带版本并有容量上限，localStorage 不可用时仍能工作。退出时暂停本地播放器、移除 src、回收对象 URL、清空资源内存缓存。

## 11. 错误与恢复文案

| 条件 | 用户理解的提示与操作 |
| --- | --- |
| 未登录 / 会话变化 | 使用原登录入口；恢复后重新核验来源与报价，不自动开始付费/耗次任务 |
| CLIPS_DISABLED / ALLOWANCES_DISABLED | “切片功能暂未开放”；关闭创建入口，已有结果仍可尝试只读读取 |
| CLIP_TIMING_NOT_CONFIGURED | “暂时无法生成视频，可先查看候选”；不让用户去配置模型 API |
| 无精彩片段 | “没有找到符合当前条件的片段”；显示后端原因，调整条件/查看原文 |
| CLIP_SOURCE_REQUIRED / CLIP_SOURCE_MISMATCH | “生成新片段需要原视频，请重新上传同一文件后重新获取报价” |
| CLIP_REQUOTE_REQUIRED / QUOTE_EXPIRED / CLIP_REVISION_MISMATCH | 保留仍属于该方案的选择，重新获取报价，重新确认；不要自动提交新报价 |
| CLIP_TIMING_UNRELIABLE | “暂时无法可靠定位所选片段，请减少选择或换其他候选”；不自动猜测边界 |
| CLIP_SELECTION_OVERLAP / CLIP_DURATION_INVALID / CLIP_RANGE_UNAVAILABLE | 保留结果和勾选，解释需要调整选择；可从单项重试查找问题，不替用户截断原句 |
| CLIP_TIMING_BUDGET_EXCEEDED | “本次定位范围较大，请减少所选片段”；不推荐升级套餐来绕过与套餐无关的预算 |
| CLIP_RENDER_LIMIT / waiting_for_clip_render_limit | “今日视频处理次数已达上限”；不要误称转写/AI 余额不足；日界按北京时间，不展示无依据的精确剩余数 |
| CLIP_EXPORT_IN_PROGRESS / TASK_ALREADY_RUNNING | 找到已有任务则继续跟踪；查不到时提示打开任务历史，不重复创建 |
| 文件 404 / 凭证过期 / 403 | 先刷新元数据和身份；有效文件重新获取短期凭证；无权或失效不无限重试 |
| 数据库/网络暂不可用 | 复用 ErrorNotice 可关闭浮层，保留输入和已有成果；确认结果不明时恢复同一报价 |

错误码、request_id 仍由现有可展开详情承载，避免在正常用户流程暴露模型名、ASR 窗口、SHA 或内部预算实现。

## 13. 实施顺序与验收门槛

| 批次 | 范围 | 完成条件 |
| --- | --- | --- |
| F1：接入与找片段 | 类型、专属报价、全局任务注册、候选阅读、空结果、历史/深链、账号隔离 | 有/无文稿均可从报价到候选；刷新恢复；不误走通用报价；不出现跨方案原文 |
| F2：生成与下载 | 勾选、冻结报价、专属确认、整批任务、逐项下载/TTL、缓存/源丢失恢复 | 原片有效、原片删除但全缓存、混合新旧文件、部分过期均正确；失败不显示部分新成品 |
| F3：视觉与可靠性 | 手机/桌面、键盘/读屏、迟到响应、弱网/重连、旧功能回归 | 下方矩阵与浏览器验收全部通过，再启用创建入口 |

创建入口增加默认关闭的前端部署开关（例如 `VITE_CLIPS_ENABLED`），只控制发现与创建，不代替服务端鉴权。开启前核对现有 `CLIPS_ENABLED`、`ALLOWANCES_ENABLED`、定位模型配置与迁移 0012。当前没有公开能力发现接口，不能用自动 POST 报价来探测功能；配置不一致时按已知错误降级。关闭创建后，已有资源深链与任务历史仍提供只读入口。首页与营销文案在 F3 验收通过后再更新，不提前宣称可实时切直播。

每批独立验证；本轮仅方案，不默认开始 F1，也不顺带改后端功能。实现期间保留已有脏工作区改动，按新增的实际差异交付。

最低验证矩阵：

1. 有文稿 0 转写报价；无文稿走后台获取；纯音频只有文字分析；正常无候选不算失败。
2. 1–5 选择、0 项禁用、修改草稿作废报价、无效/超长输入；粗时间重叠或超长不能错误拦截。
3. 连点、同一 quote 幂等恢复、确认超时、重新报价需要再次确认；方案切换不能沿用旧 selected IDs。
4. 账号切换/退出、路由变化、旧响应迟到、旧 finally，不泄露候选、报价、文件或提示。
5. SSE 乱序/重复/断线、终态事件后 GET 暂时失败、轮询恢复、缓存任务跳过中间阶段。
6. 取消与完成竞态、取消尚未确认的来源删除；新任务继续后台执行而旧成果仍可读。
7. 原片已删的全部缓存子集成功；部分未缓存需新源；缓存准入后失效要求新报价。
8. 真实 FFmpeg 成片逐项下载、共享 file_id、不同 expires_at、某项物理缺失/到期、刷新不续期、浏览器多次 Range 流量规则保持。
9. 历史缺少 file_ids 但含 clip_export_id；无 localStorage 的直接链接；隐藏历史后保留已知深链；多版文稿与方案不混用。
10. 320/375/390/768/1024/1440px、200% 缩放、横屏、安全区、长标题/6000字原文、键盘弹出无横向溢出/遮挡。
11. Tab/方向键切换分区、空格复选、可见焦点、弹窗焦点锁与关闭恢复、单次 aria-live 状态播报、减少动画。
12. 原文、总结、导图、问答、上传、下载、知识库、账户与任务历史原有用例全部回归。

实现后在 frontend 运行 `pnpm type-check`、`pnpm test:unit`、`pnpm build`，并补真实浏览器集成。使用隔离 PG/Redis/存储与显式模型替身，不能把线框脚本的成功当成生产功能已验证。若需要调整后端契约，则在 backend 用 uv 与对应测试另行验证。
